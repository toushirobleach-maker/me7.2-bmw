# Как получить аналитический BIN из SP-Daten

Скрипт:05_tools/spdaten_me72_to_bin.py. Это реконструкция для анализа; [как готовить калибровки к записи](STOCK_FLASHING_RU.md) — отдельная процедура.

## Различать HW и сборочный ZUSB

В исходном DAT header указаны ZB-NR,TYP-NR,HW-NR,IX,SW-NR. Для включённого стока:

| Поле | Значение |
| --- | --- |
| Сборочный ZUSB (колонка1) |7533625|
| Type (колонка2) |7500213|
| HW (колонка3) |7532675|
| Ревизия program |A|
| Program file, HW+revision |7532675A.0PA|
| Data ID |7533626DA → G7533626.0DA|
| EPK сборки |6901I41D|

Машиночитаемо: [IDENTITY_CHAIN.json](../00_stock/IDENTITY_CHAIN.json). Метки `hw_zb`/`zb` в старых каталогах могли использовать историческое обозначение7532675; это не основание считать его сборочным ZUSB. По одному EPK нужный вариант не выбирают.

```sh
# Все строки конкретного HW, не произвольная одна калибровка:
python3 05_tools/spdaten_me72_to_bin.py list --dat local/sp_daten/EK726.DAT --hw 7532675

# Одна однозначная сборка:
python3 05_tools/spdaten_me72_to_bin.py build --dat local/sp_daten/EK726.DAT --zb 7533625 --data-id 7533626 --sp-root local/sp_daten --epk 6901I41D -o runs/analysis_stock.bin

# Или конкретные собственные файлы:
python3 05_tools/spdaten_me72_to_bin.py build --pa local/sp_daten/program.0PA --da local/sp_daten/calibration.0DA --epk 6901I41D --expected-sha256 5ec2443311b6173e4f0bb770eb1f84c0a15a270d3bd6ac52648a77d450db5dd9 -o runs/analysis_stock.bin
```

Файлы с одинаковыми именами и разным содержимым, неоднозначная DAT-выборка, повреждённая запись, неизвестный record type или несовпадающий expected SHA останавливают сборку. Проверки выполняются до создания выхода; файлы не перезаписываются.

Наблюдаемый диалект:04 задаёт старшую линейную базу,02 допустим только с нулевым значением и не сбрасывает её;00/10 содержат bytes. Это проверено для данной пары, а не объявлено универсальным Intel HEX parser для всех BMW. Пробелы заполняютсяFF только для аналитической реконструкции.

Для известной пары результат побайтно совпадает с единственным включённым BIN:489750 bytes coverage, SHA5ec244… . В нём37/38 checksum и отсутствует cal end marker. **Результат build нельзя напрямую прошивать полным чипом или брать весь его cal64.**

Raw .0PA/.0DA/.DAT не распространяются; предоставить свои. Полного FR и ссылок на него в пакете нет.
