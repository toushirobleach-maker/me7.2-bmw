# Отдельные команды

Все примеры выполняются из корня репозитория. Офлайн-команды требуют Python 3.10+ и стандартную библиотеку. Для доступа к USB:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Ни один пример с `--execute` при сборке репозитория на машине не запускался. Для аппаратных команд явно указать свой порт: `/dev/cu.usbserial-YOUR_CABLE` — использовавшийся кабель. Не запускать две программы на одном порту.

## 1. Чтение — read.py

План без открытия порта:

```sh
python3 05_tools/read.py --kind flash
```

Полные 512 КиБ с повторным чтением всех калибровок и 16 распределённых участков:

```sh
.venv/bin/python -u 05_tools/read.py --kind flash --port /dev/cu.usbserial-YOUR_CABLE --execute
```

Для flash машина должна стоять, двигатель заглушён, зажигание II. По умолчанию применяется проверенная сессия 124800; `--baud 9600` оставляет низкую скорость. В конце скрипт восстанавливает обычную сессию и закрывает порт. Результаты — `runs/read_flash_<UTC>/`. Опция `--output новый_файл.bin` задаёт другое имя полного дампа; существующий файл не заменяется.

Обычная диагностика на 9600, без смены сессии и без требования заглушить двигатель:

```sh
.venv/bin/python -u 05_tools/read.py --kind dtc --port /dev/cu.usbserial-YOUR_CABLE --execute
.venv/bin/python -u 05_tools/read.py --kind ram --port /dev/cu.usbserial-YOUR_CABLE --execute
.venv/bin/python -u 05_tools/read.py --kind lambda --samples 16 --port /dev/cu.usbserial-YOUR_CABLE --execute
```

DTC не стираются, адаптации не сбрасываются. RAM: только известные слова FD2E/FDD8/FD50. Lambda: группы 4000/4003/4004/4005/4007 и эти RAM-слова; коэффициенты raw/32768 помечены приблизительными. Статусы DTC сохраняются сырыми, прежний эвристический ART-декодер не используется.

## 2. Проверка — verify.py

Все 38 структур целостности:

```sh
python3 05_tools/verify.py runs/my_target_512KiB.bin
```

Сравнение двух полных образов, код возврата 1 при отличиях:

```sh
python3 05_tools/verify.py runs/my_target_512KiB.bin --compare runs/my_current_512KiB.bin
```

Для файла 64 КиБ нужен контекст:

```sh
python3 05_tools/verify.py runs/my_calibration_64KiB.bin --base runs/my_target_512KiB.bin
```

Полное сравнение с машиной — только чтение, двигатель заглушён:

```sh
.venv/bin/python -u 05_tools/verify.py runs/my_target_512KiB.bin --ecu --port /dev/cu.usbserial-YOUR_CABLE --execute
```

Без `--execute` вариант `--ecu` показывает план. Возвращаются 0 при успехе, 1 при несовпадении/неверных checksum, 2 при неподдерживаемом входе или ошибке выполнения.

## 3. Контрольные суммы — checksums.py

```sh
python3 05_tools/checksums.py verify runs/my_target_512KiB.bin
python3 05_tools/checksums.py fix my_modified_512KiB.bin --output my_fixed_512KiB.bin
python3 05_tools/checksums.py fix my_modified_64KiB.bin --base runs/my_target_512KiB.bin --output my_fixed_64KiB.bin
```

Исправляются только checksum-поля. Вход не изменяется; размер 64 КиБ сохраняется. Создаётся отдельный JSON с SHA до/после и полным diff. Существующие BIN/отчёты не перезаписываются. Неизвестная разметка EPK/ROMSYS/MP отвергается. Если база 64-КиБ файла требует исправления вне cal, нужна работа с полным образом.

Коррекция математических сумм не восстанавливает отсутствующие данные или заводское происхождение. В частности, она не добавляет недостающий маркер реконструированному SP-Daten.

## 4. Запись — write.py

Только 64 КиБ `0x810000..0x81FFFF`. Допускаются полный целевой файл либо 64 КиБ, объединяемые с `--baseline`. Код вне cal обязан совпасть с baseline; обе полные сборки должны иметь правильный профиль, все суммы и проверенный маркер конца cal.

План, без порта:

```sh
python3 05_tools/write.py my_target_512KiB.bin --baseline my_current_backup_512KiB.bin
```

Команда аппаратного выполнения:

```sh
.venv/bin/python -u 05_tools/write.py my_target_512KiB.bin --baseline my_current_backup_512KiB.bin --port /dev/cu.usbserial-YOUR_CABLE --execute
```

`--baseline` — точное текущее состояние машины, не произвольный сток. Скрипт заново читает и сохраняет весь образ; при несовпадении с baseline стирание запрещено. Если цель уже полностью установлена, повторной записи нет. Для уже установленной v3 базой дальнейших правок служит свежий совпадающий дамп v3, а не исходник до патча.

Требуются неподвижная машина, заглушённый двигатель, II и поддержка питания. По умолчанию минимальное напряжение 12,5 В. Пять отсчётов должны укладываться в разброс 0,30 В. Опция `--min-voltage` принимает 11,5..14,8 В: нижняя граница отражает прежнее экспериментальное испытание, не рекомендацию для универсального прошивальщика.

После штатной проверки суммы скрипт попросит выключить зажигание полностью на 30 секунд, снова включить II и нажать Enter. Только затем полное контрольное чтение может дать **`SUCCESS_EXACT_FULL_IMAGE_MATCH`**. При ошибке нет автоматического повторного стирания, восстановления или запуска двигателя. Проверить сохранённый report перед дальнейшими действиями.

В логе сохраняются намерение до каждой передачи, ответы, резервный дамп, чтение в programming-session и окончательное чтение после цикла. Исключение UIF допускает только два фиксированных заранее прочитанных поля в программной сессии. После цикла требуется точное совпадение всего образа без исключений.

## Происхождение и границы

Эта упаковка выделяет проверенный протокол в переносимую библиотеку. Предшествующий протокол описан как испытывавшийся на одном ECU, но его private images/raw trials не входят в public clone; текущий интерфейс имеет синтетические офлайн-тесты. Это не доказательство пригодности произвольной изменённой калибровки. Функциональное ревью входного BIN остаётся обязательной частью работы по правилам AGENTS.md.

## Подготовка заводских калибровок

`prepare_stock.py` работает только офлайн: см. [STOCK_FLASHING_RU.md](STOCK_FLASHING_RU.md). Исходный37/38 stock BIN не является готовым --baseline или target. Нужны свои проверенные512 КиБ и свои matching .0PA/.0DA.

Все `runs/my_*` в примерах — собственные файлы пользователя, не включённые в репозиторий. Вызов verify для включённого аналитического stock ожидаемо возвращает1 с одной failed ROMSYS записью.
