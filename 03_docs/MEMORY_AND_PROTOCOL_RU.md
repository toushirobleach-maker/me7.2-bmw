# Память и проверенный протокол

Цель: Bosch ME7.2, M62B44LEV, DME 7532675, EPK 6901I41D. В автомобиле L322 установлен блок от E53. Детали относятся к этой сборке.

## Память

| Пространство | Адрес / размер | Смысл |
| --- | --- | --- |
| External flash | CPU 0x800000..0x87FFFF, 512 КиБ | Полный образ, который читает read.py |
| Cal sector | CPU 0x810000..0x81FFFF, file 0x10000..0x1FFFF | Единственная область записи writer |
| Internal ROM | Отдельное адресное пространство | Не получено K+DCAN-дампом внешней flash |
| EEPROM | Отдельная память | В этот образ не входит |
| FDxx RAM | В измеренных запросах 0x00FDxx | Статусы и условия |

C166 `file_offset = CPU − 0x800000` относится к внешней flash. DPP0=0x204, DPP1=0x205, DPP2=0x0E0. `EXTP #0x206` даёт `0x818000 + (mem & 0x3FFF)`. Например, логический B9CC при DPP2=E0 соответствует физическому 3839CC. Нельзя подставлять один вид адреса вместо другого без проверки конкретного диагностического сервиса.

Bitoff <0x80 в BSET/BCLR соответствует слову `0xFD00 + 2*bitoff`. Поэтому `9F17` — FD2E.9, а `9F2E` — FD5C.9. Исправление этой ошибки было принципиальным для разбора LR. [Декодер](../09_re_tools/README.md).

## Кадр и транспорт

```text
B8 destination source payload_length payload... XOR
host: destination=12 source=F1
ECU:  destination=F1 source=12
```

XOR всех байтов кадра равен 0. Локальное эхо кабеля игнорируется; оно не считается подтверждением ЭБУ. FTDI, 8E1, DTR/RTS=False, exclusive port. Ответы собираются по длине, а не ожиданием произвольной длинной паузы. NRC78 продолжает ожидание без повторной отправки.

| Запрос | Назначение |
| --- | --- |
| A2 | Идентификация, ответ E2 |
| 22 40 00 | Основные измерения, RPM, FR |
| 22 40 03/04/05/07 | Сигналы λ, адаптации и статусы |
| A0 00, A0 index | Память ошибок, ответ E0 |
| 23 addr3 length1 | Чтение flash / подтверждённых RAM-слов |
| 23 addr3 06 length1 | Чтение type06 в программной сессии |

Например, `23 00 FD 2E 02 → 63 00 1E`; little-endian слово = 1E00, биты 9/10 означают включение LR банков 1/2.

## Скорость

Обычная диагностика/запись: 9600 бод 8E1. Подтверждённое ускоренное чтение: при 9600 запрос `10 86 87 → 50 86`, затем host 124800. Возврат: `10 86 10 → 50 86`, host 9600, `10 81 → 50 81`, A2. Простая смена baud компьютера режим ЭБУ не меняет.

По описанному прежнему частному измерению (raw logs не распространяются): короткий RAM-запрос около 63 мс, группа 4000 около 114 мс, пять групп подряд около 413 мс. Оценки предельного опроса без добавленных пауз — 16, 9 и 2,4 набора/с соответственно; устойчивый максимум не измерялся. Flash на 124800 — около 3,4 КБ/с. RAM/live на повышенной скорости при работающем моторе не испытаны.

## Программирование

Штатный challenge/seed/key из 10EK726, одна попытка ключа. Переход `10 85 01`; явный NRC21 допускает ограниченный повтор того же запроса. Сессия85 не возвращалась в обычное приложение простым 1081 — использован физический цикл зажигания.

| Этап | Payload |
| --- | --- |
| Erase cal | `31 02 81 00 00 06 00 00 00` |
| Download 64 KiB | `34 81 00 00 06 00 01 00 00` |
| Transfer | `36` + 128 байт, без UDS-счётчика в запросе |
| ACK transfer | `76` + BE16 счётчик блоков 1..512 + status |
| Transfer exit | `37 → 77` |
| Native checksum | `31 01 → 71 01 00` |

Из erase-параметров нельзя выводить размер как из обычной записи памяти: это адресная OEM-операция. Ограничение именно 810000..81FFFF проверено по коду loader и фактическому результату. Полный erase/write 512 КиБ не реализован. Повторяются только явно разрешённые отрицательные busy-ответы; таймаут команды стирания/передачи никогда не вызывает слепой повтор.

## UIF и обратное чтение

В первой записи type06 read показал 75 служебных отличий в file 1FD26..1FD43 и 1FD54..1FD81. После native checksum и цикла зажигания полное чтение совпало с целью. Точный механизм подстановки не установлен.

Writer заранее читает эти поля в той же программной сессии. До переключения допускается точный target либо target с точными заранее сохранёнными полями; неизвестные отличия останавливают проверку. После переключения требуется точный full target, без масок. Native checksum и приём блока по ACK не заменяют полное чтение после цикла.

Оригинальные wire-эталоны: [07_evidence/protocol](../07_evidence/protocol/README.md). Новая упаковка state machine проверена офлайн; испытания на машине относятся к сохранённым предшествующим скриптам.
