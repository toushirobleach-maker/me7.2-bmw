# KFZW* — offline block pass-3

**Вердикт:** `OFFLINE_BLOCKED` (не PROVEN). В патч не поднимать.

Декодер: только `review_decode.py` (калибровка `9F17` / `D7400602` / `C2F43016` — OK).

## Негатив pass-3 (доказано кодом)

1. `MOV R13,#0x204` / `#0x205` — **0**.
2. Far-ptr `MOV R12,#imm; MOV R13,#0x204/#205` перед любым `B704/B524/BB20/BB94` — **0**.
3. `R12∈{0x0220,0x0320,0x0BC2,0x0D42,0x0EC2,0x0F0A,0x0FCA}` перед интерполятором — **0**.
4. `EXTP #0x204/#0x205` — **0** (при `#0x206` = 1716).
5. Чтение слотов дескрипторов `0x7946` / `0x79AC` (там лежат `0220`/`0BC2`) — **0**; читаются соседние `0x7944`→`0x2CBC`, `0x79BE`→`0x2EBC`.
6. `CALLS 0x00,0x791A` — 2 сайта; тело по `file 0x791A` = `FFFF` (internal ROM / seg0 вне внешнего дампа).

## Что есть (не consumer)

- Cal-таблица @`0x17946`: `0220 0320`; @`0x179AC`: `0BC2 0D42 0EC2`; @`0x179B8`: `0F0A 0FCA`.
- Car-dump меняет байты KFZW* → данные «живые», путь потребления в этом 512 KiB не виден.

## Условие снятия блока

Инструкция (или доказанный обход через ROM-helper с читаемым телом), где база `0x810220` / `0x810BC2` (стр. `0x204`) реально подаётся в интерполятор; затем отдельно — размерности и signed×0.75 на этом пути.
