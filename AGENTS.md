Отвечать по-русски, конкретно. Начать с README.md, 03_docs/START_HERE_RU.md и 03_docs/STOCK_FLASHING_RU.md.

## Назначение

Исследование одной компоновки Bosch ME7.2 /7532675 /6901I41D. External flash512 КиБ; cal=file10000..1FFFF /CPU810000..81FFFF. Полная запись512, boot recovery, EEPROM/IROM и другие сборки не реализованы.

## Публичная политика — обязательна

- В Git допускается только один исходный BIN: `00_stock/ME72_7532675_6901I41D_stock_from_G7533626_512KiB.bin`, SHA5ec2443311b6173e4f0bb770eb1f84c0a15a270d3bd6ac52648a77d450db5dd9. Это аналитическая реконструкция37/38, не flash-ready image.
- Дампы/модифицированные сборки/калибровки/сырые логи/VIN/идентификаторы и реальные security-ответы машины не публиковать. Transfer-логи могут восстанавливать полный cal, даже без BIN.
- Полный FR PDF на1043 страницы, его текст/страницы и ссылки на PDF либо содержащие его архивы не публиковать. Допустимы сохранённые индексы названий/страниц без download URL.
- Собственные входы хранить в gitignored `local/`, результаты в `runs/`. Не удалять их у пользователя и не добавлять в публичный manifest.
- Не возвращать private-артефакты ради устранения missing-reference предупреждений. Их отсутствие намеренное и отражается отдельным классом.
- Перед публикацией: check_public_tree.py, manifest verify, анализ отчётных ссылок и чистая Git-история. Подготовка репозитория не означает разрешения публиковать его в GitHub.

## Доказательства

PROVEN — записанное утверждение с consumer, независимой семантикой и falsifier. STRUCT/HYP/UNLINKED не основание менять функциональный байт. Статусы155/99/298/80 унаследованы; byte-check не переутверждает смысл/размерность. Функциональная правка требует отдельного diff/отчёта. E5A0/E650/community адреса не равны6901 без подтверждённого потребителя.

Не форсировать B_lr/B_lr2. Class0 описывает регистрацию DTC, не полное отключение монитора. Технический механизм SAP→LROBD можно объяснять по публичным листингам, но сырые полевые испытания в этот репозиторий не входят.

В известной DAT-строке assembly ZUSB=7533625,HW=7532675,IX=A,data=7533626DA. Program filename uses HW+IX. Не путать column1/column3 и старую метку hw_zb.

## Инструменты и ограничения

- read/write без --execute — офлайн-план. Не открывать порт и не отправлять запросы без явного пользовательского запроса соответствующего действия.
- Writer — только64 КиБ, собственный свежий512 baseline, checksum/profile/marker checks и точный postcycle full read. Таймаут destructive request не повторять. Не добавлять raw SID/erase/force или автоматическое восстановление.
- UIF-исключение только для двух фиксированных неизменяемых полей и точных pre-erase bytes; после цикла full image должен совпасть без исключений.
- prepare_stock.py — только overlay данных .0DA на собственный baseline. Известные .0PA program bytes должны совпасть. Непокрытые байты и определённые служебные поля сохраняются, checksum пересчитываются. Это не полная заводская перепрошивка и не универсальная карта VIN/ISN.
- Исходный аналитический stock не менять. Checksum-fix меняет только поля хранения сумм в отдельном файле, включая ROMSYS вне cal; это не разрешает писать код.
- Подбор аппаратуры/ZUSB/варианта, кодирование и штатное согласование EWS отдельно. Не исправлять несовместимость изменением VIN и не предлагать EWS-off как шаг подготовки стока.

## Адресация / якоря

CPU=file+800000; DPP0=204,DPP1=205,DPP2=E0. EXTP206→818000+(mem&3FFF). Bitoff<80→wordFD00+2*bitoff:9F17=FD2E.9,9F2E=FD5C.9. B9CC/B9D6 при DPP2=E0→3839CC/3839D6. FDxx читались как00FDxx. Не смешивать file/logical/physical/service-address.

ESKONF table11B2C, SLP@11B2F,SLV@11B31,inactive=11. CWKONLS@1A5EA,SAP@1A5EC. FD50&3C00=3000 — конфигурация наличия зондов. LROBD@87582C,FDD8.9/.10 — запреты, FD2E.9/.10 — B_lr/B_lr2. ROMSYS→canonical MP pairs→34MP→CRC32[10000:1FC04]@1FC0E LE. KRKTE@19CC4 — recorded PROVEN. KFZW/page204 недостаточно раскрыты без IROM/трассы; FFFF внешнего файла не сообщает содержимое внутренней ROM.
