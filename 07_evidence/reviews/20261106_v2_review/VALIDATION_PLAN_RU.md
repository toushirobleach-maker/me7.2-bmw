# Исправленный план проверки кандидата v2

Это план будущего измерения, не отчёт о выполненном испытании. Текущий BIN ещё имеет замечание по диагностике задних нагревателей; сначала требуется решить его. Ни одна операция с автомобилем данным ревью не выполнялась.

## Адреса и ожидаемые состояния

Память читать с учётом адресного пространства конкретного сервиса. Для 16-битовых адресов данных DPP2=E0 даёт физический адрес `0x380000 + (logical & 0x3FFF)`; FDxx относится к другой области. Слова интерпретируются little-endian.

| Что проверить | Адрес в коде | Физический адрес при штатных DPP | Критерий |
|---|---|---|---|
| Наличие λ-зондов | FD50 | 00FD50 | **`word & 3C00 == 3000`** |
| SAP отсутствует | FDC0.11 | 00FDC0 | `word & 0800 == 0` |
| Эффективный ESKONF[3] | 8CB4 | 380CB4 | FF, пара SLP=11 |
| Эффективный ESKONF[5] | 8CB6 | 380CB6 | F3, пара SLV=11 |
| Статус SLP | B9CC | 3839CC | bit0=0 после корректной инициализации |
| Статус SLV | B9D6 | 3839D6 | bit0=0 после корректной инициализации |
| Коллективный запрет LR | FDD8 | 00FDD8 | bits9/10: `word & 0600 == 0` |
| KATV: B_nokatfz | FDD8.7 | 00FDD8 | Зафиксировать значение, не форсировать |
| Разрешения диагностики | 904A | 38104A | Особое внимание mask0080: DHLS задних нагревателей |
| λ-регулирование | FD2E | 00FD2E | bits9/10 активны при выполнении **всех** условий LREB |
| Прочие источники LROBD | FD8E.13, FD72.9, FD42.6 | 00FD8E, 00FD72, 00FD42 | Зафиксировать вместе с SLP/SLV и FDD8 |
| Внутренние условия LREB | FDDA, FDDC, A7E8 | 00FDDA, 00FDDC, 3827E8 | Для разбора оставшихся запретов по текущему листингу |

Маски в таблице — hex. Например, для FD50 передние биты **12 и 13** должны быть 1, задние **10 и 11** — 0. B_lsv/B_lsv2 — флаги наличия; готовность датчиков проверяется отдельно диагностическим ответом и поведением сигнала.

## Последовательность оценки

1. Сохранить исходный DTC-лог и статусы. При последующем стирании DTC учитывать, что старые записи не характеризуют работу нового ПО. Сброс всех адаптаций не следует автоматически из необходимости очистки DTC.
2. Проверить инициализацию: эффективные ESKONF, паспорт SAP и маску наличия зондов. Диагностический идентификатор ПО сам по себе не доказывает, что внутри нужные байты v2: SW-ID не менялся.
3. Снять достаточно близко по времени SLP/SLV fault bit0, остальные три входа LROBD, FDD8 и FD2E. Разнесённые по времени чтения не являются атомарным снимком.
4. Убедиться, что передние датчики прогрелись и дают пригодный сигнал. Затем оценить B_lr/B_lr2, fr1/fr2 и обучение адаптаций в подходящем стабильном режиме. Неподвижный fr или нулевая адаптация по одному короткому наблюдению не устанавливают причину.
5. Проверить задние нагреватели после распознавания KATV нормального варианта: при B_nokatfz=0 в **текущем v2** CDHSH=0 всё равно разрешает их диагностику. Не считать отсутствие ошибок сразу после сброса окончательным результатом. Нужны DTC 0E/04, фактический DHLS-enable и статусы путей 3A/3B.
6. Если SLP/SLV очищены, а LROBD остаётся, разбирать три остальных входа. Если LROBD снят, но LR не включился, разбирать реальные LREB по FDDA/FDDC/A7E8 и датчикам. TLRHS — только один временной элемент, не температура и не универсальный срок начала регулирования.
7. Оценивать расход после подтверждения работающего LR и проверки остальных неисправностей, на сопоставимом режиме и по достоверному измерению. Из прежнего 28-секундного лога нельзя вычислить ожидаемое снижение расхода.

Для пути нагревателей классы расположены по **11613/11614**, их состояния DFPM — логические B95A/B95C, физические 38395A/38395C при DPP2=E0. Полное снятие разрешения и обнуление класса регистрации — разные решения; план не предписывает автоматическую правку ни одного из них.
